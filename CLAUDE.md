# cuems-power-bridge

Part of the **CUEMS** ecosystem — see the [`cuems-RELATIONS`](https://github.com/stagesoft/cuems-RELATIONS) repo for the system index, architecture diagram, and protocol/port map.

## Role

**Controller-only** power + showcontrol bridge: an asyncio HTTP coordinator on `:8478` fronting orderly cluster shutdown and GO/STOP. Triggered by a wired **Shelly Pro 1** flip-switch or a **Bitfocus Companion** Stream Deck. Holds persistent WebSockets to the engine (`:9190`, binary OSC — status cache + GO/STOP) and editor (`:9092`, JSON — `project_ready` boot auto-load). Python 3.11+, dh-virtualenv into the shared venv `/usr/lib/cuems/`. Service `cuems-power-bridge.service` (the unit is shipped by **this package**, `debian/cuems-power-bridge.service` → `/lib/systemd/system/`; older notes saying cuems-common ships it are wrong), config `/etc/cuems/power-bridge.conf`. `dry_run=true` logs SSH/Shelly/poweroff instead of executing. **Commits are GPG-signed** (retry on "gpg failed to sign", never `--no-gpg-sign`).

**Renamed from cuems-wsclient** (2026-06, v0.2.6 — complete). Import package `cuemspowerbridge` (`src/cuemspowerbridge/`), Debian source+binary `cuems-power-bridge`, repo `stagesoft/cuems-power-bridge`. The **only** intentional legacy survivor is the backwards-compat console entry `cuems-wsclient` → `cuemspowerbridge.wsclient:main_cli` (the impl file is still `wsclient.py`). Notes pointing at `src/cuemswsclient/...` are stale → `src/cuemspowerbridge/...`.

## HTTP contract (`:8478`, JSON `{"ok": bool, "reason"?: "<token>"}`)

- `GET /status` → `state`, `engine_state`, `nodes_pending`, `shelly_timer_armed_s`, `last_error` (+ brightness/display keys).
- `POST /go` → `/engine/command/go` (409 `not_armed` if the engine isn't armed).
- `POST /stop` → `/engine/command/stop`.
- `POST /shutdown[?force=1]` → orderly shutdown. Refuses 409 `project_running` unless `force=1` or `refuse_if_running=false` (**consistent with the project-wide "never auto-stop a running project" rule**; a LOADED-but-not-playing engine is NOT "running"). Other codes: 409 `shutdown_already_in_progress`, 503 `engine_state_unknown`, 502 `shelly_unreachable`, 401 `bad_token`.
- `POST /setnextcue` / `POST /gocue` — cue triggering (shipped in 0.3.0-5).
- `GET /status` carries `nextcue_name` (0.3.0-9): `EngineClient` caches the engine's `/engine/status/cue_name/<uuid>` broadcast (cuems-engine ≥ 869fedahu — sent **after** `load`, so a change of `load` empties the cache and the burst refills it; emptied on disconnect). `""` against an older engine.
- `POST /brightness?level=<name>` — projector brightness presets via Epson ESC/VP21 over ESC/VP.net (TCP 3629); 200 all / 207 partial / 502 all-failed / 400 unknown_level / 503 none.
- `POST /poweron[?wait=1]` / `POST /poweroff[?wait=1]` — projector power (PJLink) on demand. **`/poweroff` is DISPLAYS-ONLY**: it never powers a machine off (that is `/shutdown`). Checks: 401 `bad_token` → 429 `rate_limited` → 503 `no_displays`. Both share `_projector_power_lock`: each cancels+awaits the other's in-flight task, then spawns its own or joins its own in-flight one → **last request wins at task level** (a projector may still ERR3 while warming/cooling). `/poweroff` queries first (`status_all`) and sends POWR 0 only to devices not already OFF/COOLDOWN (`DisplayManager.power_off_where_needed`, same rule as cuems-common's `cuems-cluster-poweroff`). **Default (no `wait`): 200 at once, fire-and-forget** — `cuems-displays-on` (cuems-common) depends on this; don't change it. **`?wait=1`**: awaits the task, bounded by `3×projector_command_timeout_s+5` s (`/poweron`) or `4×…+5` s (`/poweroff`: +1 timeout for its query), and answers like `/brightness`: 200 all OK/already there, 207 `partial` or `unconfirmed` (ERR3), 502 `all_failed`, each with per-device `results` (`name`, `ok`, `state` on/off/already_off/unconfirmed, `error`); 504 `timeout` (the task keeps running); 409 `superseded` (cancelled by an opposite request). `_run_shutdown` neither uses nor cancels the `/poweroff` task (it runs its own `power_off_all`), and the startup/on-load power-on paths don't take the lock.

- **NDI preview for montajes** (`/ndi/*`, CLI `cuems-ndi-preview`; ClickUp 869ekxuez, plan `cuems-RELATIONS/Plans/2026-10-08-ndi-preview-montajes.md`) — puts an NDI source on any node's output **while no project is loaded**. Needs **cuems-videocomposer ≥ 0.1.2-7** on the target (OSC `ndi://` load, `fit_output`, `ndi/discover`). Code: `ndi_preview.py`.
  - **Operator surface (rev 10): sources and screens only.** A screen is named by its UI name (`<name>` in the controller's `/etc/cuems/default_mappings.xml`, e.g. "Monitor derecha"), by `<role_id>_<connector>` (e.g. `node01_HDMI-A-1`) or by its number in `/ndi/outputs`; a UI name used on several machines → `409 ambiguous_output` with the candidates. The tool works out the machine and the route (direct, or the controller's relay). **One preview per screen** (layer `ndi-preview-<connector>`); one load in flight per machine (`409 busy`). Catalogue: `ndi_screens.py` (mappings ⨝ `network_map.xml`, per-project mappings ignored like the engine does).
  - **Sizes and machine health (rev 12.2).** Screens carry `mode`/`region` from each VC's `output/list` (cached per machine in `_outputs_info`). A preview's source size comes ONLY from its own layer's `fit_output … (dims WxH)` line (`fit_size`); fps only from the open-time `NDI: Source format:` line in its confirm window, never overwritten. `"Source format updated/changed"` lines carry no layer id: never attribute them. `pixel_scale` = screen px per source px against the REGION (fill `min(rw/w, rh/h)`, native capped at 1, as the VC's `OutputFit.h` places it; the VC's own fit `scale` is canvas-relative, not pixels). `ndi_health.HealthMonitor` probes off the request path every 5 s while the page is used (stops after 10 min idle, never during a show): node = ICMP ‖ TCP/22 ‖ journal written < 60 s, `unreachable` after 2 failed cycles; controller = `systemctl is-active cuems-videocomposer` (`vc_down`). Requests only read it: `show` refuses `503 machine_unreachable` / `vc_down` / `journal_stale` (journal older than `ndi_journal_stale_s`, default 600) before resolving or sending; `sources`/live `outputs` skip those machines; `stop` is never blocked. A confirm timeout reason is a token (`no_vc_reply` or the health reason), the English goes to `detail`. `/ndi/status` carries `machines`, `/ndi/outputs` each screen's `machine_state`.
  - **Sources on another subnet, by IP (rev 12.2 §3.10).** Extra IPs = `ndi_hosts` in `power-bridge.conf` (seed, survives restarts) + `POST /ndi/hosts {"ip"}` / `{"ip", "remove": true}` from the page (in memory); `GET /ndi/hosts`. Each one is checked by `check_host_ip` (dotted unicast IPv4, never a comma — it would smuggle a second entry into `p_extra_ips` — nor the controller's own addresses), cap 8. Only the **controller's** discovery gets them (`/videocomposer/ndi/discover <s> <ips>`); its `started … ips=<n>` line is the capability check (`409 hosts_need_controller_vc` without it, and the IP is dropped). Finds tagged `(ip)` become `via_ip` sources. **Route:** controller screens load `ndi://@ip:port` (the VC's receiver has its own finder without the extra IPs, so a by-name load would fail) after a 2 s TCP precheck of that stream port (`502 source_unreachable`); node screens use the relay. Adding/removing a host waits for an in-flight discovery and runs a fresh one.
  - **No token on `/ndi/*`** (D30, Ion 2026-10-09: like the CUEMS UI, open on the internal network until there are users). `shared_token` still guards every other endpoint and must never be put in the page (it would hand out `/shutdown`, `/go`, `/poweroff`); a valid token only adds the relay upstream/bytes to `/ndi/status` (D22). With no token in the way, **D27 (JSON only) is the CSRF barrier** — don't loosen it.
  - **Operator page (rev 11): `GET /ndi/`** (`data/ndi_page.html`; `/ndi` → 301). One self-contained file: inline style + script hashed into a strict CSP at startup (`load_page()` — keep tag names out of the page's HTML comments or the hash shifts), `X-Frame-Options: DENY`, names rendered as text only; relative URLs (works behind a future apache prefix, D28). It is a thin client of the same endpoints as the CLI and Companion; `tests/test_ndi_page.py` fails if a new reason token or preview state lacks Spanish text in the page's `REASONS`/`STATES`.
  - `GET /ndi/sources` → one cluster-wide list `[{n,name,seen_by:[machines]}]` (`#n` indexes it); refused like a show (409 `project_loaded`/`project_running`, 503 `engine_unknown`) so nothing pokes the VCs of a show. `GET /ndi/outputs` → every screen `[{n,name,alias,machine,connector,present}]` (`present` from each VC's live `region` lines; while a show blocks previews, the catalogue only — `present: null`, no VC asked).
  - **POSTs take JSON only** (D27): any other `Content-Type` → `415 bad_content_type` (closes the no-preflight form/`text/plain` path from any web page when `shared_token` is empty); unparseable body → `400 bad_body`; the old query-string form is gone.
  - `POST /ndi/preview {"source":"#1"|name|substring,"output":"<screen>","mode":"fill"|"native","wait"}` → **202 `confirm:"pending"`** right after the OSC; `wait:true` blocks ≤15 s → 200 `frames`/`no_frames_yet`/`unconfirmed` or 502 with the VC's verdict (`source_not_found`, `unknown_output` — the layer is unloaded, `load_failed`, `stopped_or_reset_during_load`), 409 `raced_by_load`. Refusals: 409 `project_loaded`/`project_running`/**`auto_load_active`**/`busy`/`ambiguous_source`, 503 `engine_unknown` (`force_unknown_engine:true` overrides only this), 503 `journal_unreadable` (path named), 404 `source_not_found`, 400 `bad_node`/`bad_output`/`bad_mode`.
  - `POST /ndi/stop {"output":"<screen>"}|{}` (`{}` = every screen of the catalogue, so previews from before a bridge restart are cleared too; never refused by the guard). `"output": ""`/`null` → `400 missing_output` — only a body without the key means all. `GET /ndi/status` (unauthenticated, like `/status`; one computation per second shared by every caller, cached apart for token/no token so D22 holds): engine state, **`blocked`** (the guard's reason token or null), auto-load state, **per screen** the source, route, `confirm`, `wiped` (the VC logged `Reset: removing all layers` after it — an engine load/STOP), `stopped`; relays.
  - **How it knows**: the VC has no reply channel, so every answer is a **journal line** (`SYSLOG_IDENTIFIER=Cuems:videocomposer`; formats pinned by the VC's `remote/JournalContract.h`). Local VC: the local journal, cursor. Node: its uploaded `/var/log/journal/remote/remote-<ip>.journal` (+ rotated `@` files), cursor; without that file, `--merge _HOSTNAME=` with a 10 s skew margin (journalctl refuses `--since` with `--after-cursor`). The unit therefore runs with **`SupplementaryGroups=systemd-journal systemd-journal-remote`** — the bridge can read every host's journal.
  - **Targets**: the master entry is **always `127.0.0.1`**; a node's `<role_id>.local` is used only if it resolves to 169.254/16 through the cluster interface or equals its `<ip>`, else `<ip>` — role_ids repeat across clusters on a shared LAN (test2/test3, Medina) and avahi answers on the uplink too.
  - **One request per VC at a time**: the per-address lock is held until the VC logs how the load ended (`Async load complete/failed`, `Layer no longer exists`, cancelled) — two overlapping loads of one layer id would show the first while confirming the second.
  - **Auto-load wipes previews**: while `auto_load_project` is set and the once-only auto-load has not completed **in this bridge process** (any restart re-arms it, the deb's postinst restart included) or `auto_load_persistent=true`, the loop reloads the project as soon as the engine is idle → `/videocomposer/reset` → preview gone. `show` refuses with `auto_load_active`; for a montaje, let the auto-load finish, or empty `auto_load_project`.
  - Reach: a laptop on the nodes' switch reaches every node directly (adapter on DHCP/automatic, or `169.254.0.0/16` on-link). **A laptop on the venue LAN or the controller's WiFi reaches the nodes through the relay** (rev 9, `ndi_relay.py`): when the node's own discovery lacks the source and the controller's lists it, `show` opens a TCP relay on the controller's cluster-side address (`src` of `ip route get <node>`) to that one source and the node loads `ndi://@<relay>`. **No re-encoding**: the node's NDI receive runs over NDI's base TCP connection (videocomposer ≥ 0.1.2-7 logs `NDI receive transport: base TCP`; without that line → `409 relay_needs_vc`; a controller VC without source addresses → `409 relay_needs_controller_vc`; upstream down → `502 relay_upstream_unreachable`, checked before anything is sent). The relay accepts **only the target node's address** (the controller answers ARP for its cluster address on every interface, so binding alone is no boundary), ≤ 4 concurrent connections, keepalive + `TCP_USER_TIMEOUT` 10 s, and a watchdog closes it on a project load/run, after 30 s without a node connection, on `stop`, on the next `show` (after the unload) and at bridge stop; a bridge restart drops relays (the layer freezes; `stop --all` clears it). `/ndi/status` shows relay state; the upstream address and bytes only with a valid token. Cost: each relayed node is one more stream out of the sender (a WiFi laptop's upload) and through the controller. Unplug the laptop before the show — VC OSC :7000 is unauthenticated.

- `POST /loadproject?project=<uuid>|name=<name>[&wait=1|check=1|force=1|reload=1]` / `POST /unloadproject` / `GET /projects` — load/unload through the editor like the UI (plan `cuems-RELATIONS/Plans/2026-10-13-power-bridge-load-unload-project.md`, 0.3.0-11). **Never stop a show**: 409 `project_running`. Load answers 202 and is tracked in `/status.project_op` (`loading`→`armed`/`degraded`/`failed`/…); `wait=1` waits; `check=1` is a dry run. **One editor request at a time** (409 `previous_request_pending`): the editor runs a session's requests concurrently, so a later unload could overtake a slow load — `EditorClient` matches replies to registered requests, single-flight for `project_ready`/`project_unload`, slot freed only by the reply or a disconnect. A node **the project needs** (script.xml outputs ∩ `<adopted>` − controller from `settings.xml <node><uuid>`) off the NNG bus → 409 `nodes_not_ready` (`force=1` → `degraded`); unused nodes never block; an unknown bus state never blocks. Same project while loading → joined; freshly armed (arm after a load, not played) → `already_loaded`, anything else reloads. Loading another project or unloading **suspends auto-load until restart** (`/status.auto_load.disabled_reason`); loading the auto project counts as its load. Unload is controller-side (nodes keep players resident; `/tmp/cuems.show.lock` stays). Key `project_op_timeout_s` (str, lenient, 60..3600, default 450).

- **Companion cue-status relay** (`osc_relay.py`, plan `cuems-RELATIONS/Plans/2026-10-09-power-bridge-companion-cue-status-relay.md`) — re-sends `/engine/status/*` over **UDP OSC** to Companion's Generic OSC module (it cannot read the engine's binary-OSC WebSocket). **Off unless `osc_relay_targets` is set**; controller only. Contract (README "Companion cue-status relay"): matching frames forwarded **byte for byte** (`osc_relay_keys`, default `cue/,running,armed,load,nextcue`); `/cuems/bridge/engine_connected i 0|1` (a change jumps the queue, heartbeat 2 s); **integer edge pulses** `/cuems/bridge/cue_started|cue_ended/<uuid>` sent `0`→60 ms→`1`→150 ms→`0` — a self-clearing no-argument message was proven to fire Companion triggers 0/20 (module-base 5/25 ms + trigger 10/20 ms debounces), the pulse 20/20 (spike P, `cuems-RELATIONS/baselines/companion-relay/`); `/cuems/bridge/dump` on UDP `osc_relay_listen` (default `127.0.0.1:8478`) re-sends the cache to the configured targets only.
  - **Hold rule**: per-cue frames (`cue/`, `cue_enabled/`, `cue_name/`) are held while the relay's view of `load` is unknown or `""`, committed on a non-empty `load`; `load ""` and a link drop synthesise `cue/<uuid> = 0` for every committed cue. This is what makes both engine load orders (≤ rc6-3 burst-then-load, rc_1/rc6-4 `load ""` first) and a failed load come out right. Edges are live-only: never from commits, resets, or within 2 s of a connect.
  - **Config never raises**: the five `osc_relay_*` fields are `str` in `Config` and parsed by `OscRelay.from_config()` (`op_budget_s` precedent) — cuems-common's `cuems-cluster-poweroff` exits 3 on any `config.load()` error. Bad targets/keys → relay disabled + `last_error`; bad listen → listener off; rate/refresh clamp with one warning. `osc_relay*` typos land in `/status` `osc_relay.unknown_keys`.
  - Isolation: `from_config`, `start()` and `stats()` failures never take the bridge or `/status` down; hooks (`EngineClient.on_frame` / `on_connect` / `on_disconnect`) are registered **before** `engine.start()`; `close()` runs after `engine.stop()` (link 0 first, trailing `0` of in-flight pulses, then a 0.5 s flush).
  - **A dev bridge next to the installed one must blank `osc_relay_*`** (or move the ports): two relays on one listen port → the second's listener is disabled; two relays on one Companion port interleave.
  - A natural end leaves `running = yes` and the cues at `100` until STOP (engine design); STOP resets every cue to `0` with no `cue_ended`.

All endpoints validate the optional `X-Auth-Token` header against `power-bridge.conf:shared_token` (`/status` is unauthenticated).

## Shutdown flow (fail-safe ordering)

asyncio-lock (concurrent calls → 409) → token + refuse-if-running guard → parse `network_map.xml` for every `NodeType.slave` avahi hostname (`role_id.local` / `alias.local` / `hostname.local`, **never** raw `<ip>`) → parallel `ssh cuems-admin@<host> sudo /sbin/poweroff` (fire-and-forget) → reachability poll (ICMP + TCP/22) until silent or `shutdown_max_wait_s` → Shelly `Switch.GetStatus` pre-check (abort if already off) → arm Shelly hardware safety timer `Switch.Set {on:true, toggle_after: shelly_safety_timer_s}` → local `sudo systemctl poweroff --no-block` → Shelly cuts mains on the already-off box. **Fail-safe:** if the Shelly RPC fails after 3 retries the bridge does NOT poweroff locally (returns 502) — staying up beats powering off without a confirmed mains-cut deadline.

## Boot auto-load

If `auto_load_project=<uuid>` is set, the bridge sends the editor `project_ready` when the engine reports an empty load state. `auto_load_persistent=false` (default) fires once per bridge process; `=true` on every observed empty-load. 3 consecutive failures disable auto-load for the session. `auto_load_node_settle_s` gates how long after seeing nodes on the hub the first `project_ready` fires — set it **above node player-registration time** (nodes register players ~28s after hub-join; a too-early settle arms only the controller and the load stalls on the engine's 120s arm watchdog). Proven config: `settle=45`, `armed_timeout=125`.

## SSH node poweroff

The poweroff SSH goes through the **`cuems-admin`** operator account, NOT the `cuems` service account (`cuems` is `/usr/sbin/nologin`). The dedicated bridge key `/etc/cuems/power-bridge.key` is written **locked** in each node's authorized_keys: `restrict,command="sudo /sbin/poweroff" ...` — a leaked key can do nothing but poweroff. Sudoers drop-in (cuems-common): `cuems-admin ALL=(root) NOPASSWD: /sbin/poweroff`. Distribute keys with `cuems-power-bridge-deploy-keys node01.local …` (run as the operator, writes the node's own authorized_keys with plain tee — no sudo, resolves `$HOME` remotely). NB: the ssh returns rc=255 as the node goes down — expected; success is judged by the reachability poll, not ssh rc.

## Shelly mJS

`/usr/share/cuems/shelly-mjs/cuems-shutdown.js` (`cuems-power-bridge-install-mjs`) is pasted into the Shelly Scripts tab; reacts to SW0 → OFF and POSTs `/shutdown`. The SW0 input is a **flip-switch** (not momentary) — `addStatusHandler` fires only on deltas. The mJS must be **ASCII-only** (`Script.PutCode` rejects non-ASCII, -103) and uses `controller.local`. `shelly_url` in the *bridge* config, by contrast, must be an **IP** (Shelly mDNS is unreliable). Shelly gotchas (learned wiring this):

- **`HTTP.POST` silently drops a custom `headers` map** — it only honors `content_type`, so `X-Auth-Token` never goes out and every `/shutdown` 401s. Use `Shelly.call("HTTP.Request", {method:"POST", url, body, headers:{...}})` — the only Shelly HTTP call that transmits arbitrary headers.
- **KVS is not a JS global** — call `Shelly.call("KVS.Set", ...)`.
- **A standalone virtual component is not clickable on Home** (fw 1.7.5). To get a clickable control, create a **boolean toggle** (`view:"toggle"`) **inside a group** — the group tile renders it as a flippable switch. The badajoz web-UI shutdown is a `boolean:200` in `group:200` → flip ON → mJS catches the delta, springs it back, POSTs `/shutdown?force=1`. `FORCE` constant default `true` (hardware kill even mid-show); installer `--safe` patches `FORCE=false`.
- **`in_mode` must be `detached`** (not `follow`, which cuts power instantly on SW0 OFF) with `initial_state=restore_last`; `match_input` is an invalid combo with detached (-103). The SW0→ON branch must re-close the relay (`Switch.Set {on:true}`) so "flip up → boot" works.

## Field notes / gotchas

- **Upgrading power-bridge can silently break the ENGINE via the shared venv.** Old `.deb`s (0.3.0-1) **bundled** `python-osc` into `/usr/lib/cuems/.../site-packages`; the engine and the bridge both depend on it, but on hosts where the engine runs *editable from source* that dep was never installed into the venv — the bridge's bundle was the only copy. A newer build whose `debian/rules` **strips** pythonosc removes those files on `dpkg -i` → `ModuleNotFoundError: pythonosc.osc_message_builder` → bridge crash-loops AND the engine's OSC breaks on its next restart. Fix: restore pythonosc into the venv as **non-dpkg-owned** files (extract from the old `.deb`, `sudo cp` back). Check for this whenever bumping power-bridge. General rule: the bridge must not bundle anything another cuems package ships (websockets from cuems-utils, pythonosc from cuems-engine were both latent collisions) — `debian/rules override_dh_fixperms` strips them + `export PYTHONNOUSERSITE=1` to block `~/.local` pollution. Unique-to-bridge deps that MUST stay bundled: the aiohttp stack + typing_extensions.
- **Build on casas** (`dpkg-buildpackage -b -uc -us`; `.deb` lands in the **parent** dir) — never on the target boxes (their checkouts drift; standing rule). `dpkg -i` needs the operator (dpkg is not NOPASSWD on hardened controllers). Pre-flight the target for venv file collisions before installing (`dpkg-deb -c | ... dpkg -S`). Live hotfixes: the venv `.py` files are writable and `sudo cp` is NOPASSWD, but that yields an untracked hybrid — prefer the `.deb`.
- **Autoload vs node-boot race**: in a WoL recovery where the controller boots alone, autoload fires before nodes are up → engine load stalls after 120 s (armed never goes `yes`). A plain bridge restart then skips autoload. Recovery: `stop cuems-power-bridge; restart both engines; start cuems-power-bridge`. ⚠️ **The old symptom line is obsolete on engines carrying 869dr2kzh**: this used to read *"engine goes `project_status=none` but keeps broadcasting a stale 'loaded' over OSC"*. That contradiction was the engine's bug, not a race artifact — `project_status` collapsed loaded-but-not-playing into `none` while `/engine/status/load` correctly named the project. A current engine answers `loaded` and the two channels agree, so **`project_status=none` here now means what it says**: no project. Keep gating readiness on `armed`/`fully_ready()`, never on `project_loaded()` alone — a stalled load is genuinely `loaded`.
- **Review against the LIVE Shelly script (`Script.GetCode`) and current upstream**, not a local checkout — the casas checkout was once 23 commits behind and still on the old name.

## Future migration

The SSH-fanout poweroff is intended to be replaced by an engine-native `/engine/command/shutdown` broadcasting COMMAND/SHUTDOWN over the existing NNG bus; the external contract (HTTP shape, auth, Shelly RPC, mJS, Companion) stays the same — only `_shutdown_nodes()` is rewritten. (The original design plan `we-need-shelly-pro-jolly-chipmunk.md` is historical and no longer on disk.)
