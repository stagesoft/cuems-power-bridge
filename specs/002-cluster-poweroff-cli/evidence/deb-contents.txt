## TWO DEFECTS FOUND BY INSPECTING THE FIRST BUILD, both fixed here
  1. /usr/lib/cuems/bin also held cuems-convert-documents, cffi-gen-src,
     pwiz.py and three xmlschema-* scripts — entry points of OTHER
     distributions that pip installs for every resolved dependency. The venv
     is SHARED, and cuems-utils declares cuems-convert-documents itself, so
     dpkg -i would have refused: 'trying to overwrite ... also in package
     cuems-utils'. debian/rules stripped site-packages but never bin/.
  2. pyproject.toml still said 0.3.0 while the changelog said 0.3.1-1, so the
     .deb shipped a package whose own metadata disagreed with it.

## WHY THIS ARTIFACT IS STILL NOT SHIPPABLE
  - built on a development box, not the controller (CLAUDE.md);
  - --use-system-packages means anything in THIS host's dist-packages is
    treated as satisfied and silently omitted. Nothing was omitted this
    time, but the build is only as good as the host matching the target;
  - dependencies are unpinned: aiohttp >=3.9 resolved to 3.14.3 TODAY;
  - the cuemsutils wheel came from a working tree, not a tagged release;
  - unsigned (-uc -us).
